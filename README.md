## Prerequisites
- Node.js 18 or later
- MySQL 8 or later

## Setup
1. Install dependencies:
   ```
   npm install
   ```
2. Create the database and tables by running `schema.sql` in MySQL. Change `yourdb` to your database name.
3. Copy `.env.example` to `.env` and fill in the values:
   ```
   JWT_SECRET=<long random string>
   DB_HOST=localhost
   DB_USER=root
   DB_PASSWORD=<your password>
   DB_NAME=<your database name>
   ```
   A secret can be generated with:
   ```
   node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
   ```
4. Create the admin account:
   ```
   node seedAdmin.js
   ```
   Credentials: `admin@example.com` / `Admin@1234` (change the password outside of a demo).
5. Generate 100,000 employee records:
   ```
   node seed.js
   ```
6. Start the server:
   ```
   npm start
   ```
   The API runs at `http://localhost:3000`.

## Roles
- `POST /auth/register` always creates a `user`. Self-assigning admin is not possible.
- Admins are created only through `seedAdmin.js` or directly in the database.
- user: read-only access. admin: create, update, delete employees and run the sync.

- 500 internal server error
- 502/504 external API failure (sync)

## Task Summary

### Task 1: Employee CRUD
Create, retrieve, update and delete employees with fields id, name, email, department, designation, salary, joining date and status. Input is validated with zod. Duplicate emails are prevented by a UNIQUE constraint, and a violation returns 409.

### Task 2: Authentication
Registration and login with bcryptjs password hashing. Login returns a JWT that expires in 1 hour. The `authenticate` middleware protects `/employees`, and `requireRole('admin')` restricts write operations. The JWT secret is read from the environment, and the app refuses to start without it.

### Task 3: Top 3 Customers
The query is in `schema.sql` and is also exposed at `GET /reports/top-customers`. It excludes non-completed orders, aggregates `orders` first, applies `LIMIT 3`, and then joins `customers` for only three rows. The covering index `(status, customer_id, total_amount)` lets MySQL answer the aggregation from the index without reading table rows. Returns customer name, total orders and total purchase amount.

### Task 4: External API Integration
`POST /sync/posts` fetches posts from JSONPlaceholder.
- Timeout: 5 seconds per request
- Retries: up to 3, with exponential backoff, for network errors, timeouts, 5xx and 429. 4xx errors are not retried.
- Invalid responses: non-array payloads and malformed records are rejected or skipped and counted.
- No duplicates: `external_id` is UNIQUE and records are written with `INSERT ... ON DUPLICATE KEY UPDATE`, so repeated calls do not create duplicates.

### Task 5: Performance Optimization
100,000 employees are generated by `seed.js`. The API supports pagination and filtering by department, designation and status.
- Composite indexes: `(department, designation, status)` and `(designation, status)`
- Selective column list instead of `SELECT *`
- Page size capped at 100
- Keyset pagination (`after_id`) for deep pages
- Parameterized queries with a whitelist of filter columns

Run `node benchmark.js` with the server running. It drops the indexes, measures, recreates them and measures again.

Results (average of 20 requests, local machine):

| Scenario | Before (ms) | After (ms) | Speedup |
|---|---|---|---|
| Legacy: SELECT *, no pagination | 453.6 | 444.8 | 1.0x |
| No filter, page 1 | 43.3 | 44.1 | 1.0x |
| Department | 75.7 | 13.7 | 5.5x |
| Designation | 82.6 | 8.1 | 10.2x |
| Dept + designation + status | 128.0 | 25.5 | 5.0x |
| Designation + status | 87.9 | 4.2 | 21.2x |
| Deep page (offset) | 140.9 | 136.9 | 1.0x |
| Deep page (cursor) | 46.1 | 41.2 | 1.1x |

Indexes improved filtered queries by 5x to 21x. Paginating instead of fetching everything makes a request about 10x faster than the legacy query. Cursor pagination is about 3x faster than offset pagination on a deep page. Full details are in `PERFORMANCE.md`.
